Assignment: GET vs POST Requests

1. What are they for?

  • GET: Used to fetch or read data from a server (e.g., searching or viewing a page).
  • POST: Used to send or create new data on a server (e.g., logging in or uploading a file).

2. Where is the data sent?

  • GET: Attached directly to the URL (e.g., website.com/search?item=phone).
  • POST: Hidden inside the Request Body.

3. Security

  • GET: Less secure for sensitive data because it is visible in the URL and saved in browser history.
  • POST: More secure because data is hidden inside the request body and not saved in browser history.

4. Data Size & Type

  • GET: Limited size (URL length limits), Text only.
  • POST: No strict size limit, Supports Text, JSON, Files, Images, Videos.

5. Caching & Refresh Behavior

  • GET: Responses can be cached for faster loading; reloads smoothly on refresh.
  • POST: Responses are not cached automatically; shows a warning on refresh to prevent double submission.

Summary Table
